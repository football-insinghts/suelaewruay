# ซื้อแล้วรวย · วิเคราะห์เลข

โลโก้ของเว็บอยู่ที่ `assets/logo.png` ใช้ร่วมกันในหน้าเข้าสู่ระบบ หน้าหลัก แถบเมนู หลังบ้าน และไอคอนแท็บเบราว์เซอร์ ไฟล์นี้ตัดเฉพาะข้อมูลข้อความประกอบจาก `logo.png` ต้นฉบับออกเพื่อลดขนาด โดยคงภาพและความโปร่งใสเดิมไว้

เว็บแอป Streamlit ภาษาไทย พัฒนาจากแนวทางหน้าตาใน `baccarat-ai-main` สำหรับเกมเลข 0–9 เลือก 7 ตัว เว้น 3 ตัว

## เปิดบนเครื่องนี้

ครั้งแรกให้ดับเบิลคลิก `setup_admin.cmd` ตั้งรหัสผู้ดูแลอย่างน้อย 8 ตัวอักษรและยืนยันอีกครั้ง (ตอนพิมพ์รหัสจะไม่แสดงตัวอักษร) จากนั้นดับเบิลคลิก `start.cmd` แล้วเปิด http://127.0.0.1:8502 เข้าด้วยรหัสผู้ดูแลเพื่อตั้งรหัสสมาชิกและ AI ในหลังบ้าน

ครั้งถัดไปใช้ `start.cmd` ได้เลย หรือใช้ PowerShell ในโฟลเดอร์นี้:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8502 --global.developmentMode false
```

ติดตั้งใหม่บนเครื่องอื่น (Python 3.12):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe setup_admin.py
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8502 --global.developmentMode false
```

## สิ่งที่ใช้งานได้

- อัปโหลด PNG/JPEG ให้ Gemini อ่านตารางเป็นพิกัดช่อง แล้วเรียงคอลัมน์ซ้ายไปขวา ภายในคอลัมน์บนลงล่าง รักษาเลขซ้ำทุกงวด
- ตรวจ/แก้เลขก่อนยืนยัน ภาพไม่ชัดแสดง `?` และบล็อกการคำนวณจนแก้ครบ
- รองรับเกมที่ใช้ `10` แทน `0` ทั้งจากภาพและการกรอกข้อความ แปลง `10` เป็น `0` ก่อนวิเคราะห์ โดยหนึ่งช่อง/หนึ่งค่า `10` นับเป็นหนึ่งงวด เก็บเลขซ้ำครบ ปุ่มเพิ่มผลจริงให้ใช้ `0` เมื่อเกมออก `10` ส่วนค่าอื่นนอกช่วงและช่องที่อ่านไม่ชัดยังต้องตรวจแก้
- กรอกเลขเองได้โดยไม่ต้องมี API key หลังอ่านภาพหรือกรอกเลข ให้ตรวจแล้วกดยืนยันประวัติก่อนวิเคราะห์
- ใช้ฐานสูตรจริง 108 สูตรจากแท็บ **สูตร** ช่วง **A1:DE11** ภายในระบบ โดยซ่อนตารางฐานสูตร ลิงก์ต้นทาง และรายละเอียดเซลล์จาก UI
- ใช้ผลจริงล่าสุดเป็นเลขตั้งต้น เลข 3 ตัวในช่องเป็นเลขเว้น อีก 7 ตัวเป็นเลขเลือก เปลี่ยนเลขตั้งต้นเมื่อเพิ่มผลจริง
- ทดสอบย้อนหลังทีละงวดโดยใช้ข้อมูลก่อนงวดนั้นเท่านั้น แสดงเข้า/ทดสอบ อัตราเข้าย้อนหลัง และหลุดต่อเนื่องสูงสุดในแถบด้านบน ก่อนวิเคราะห์หรือเมื่อเปลี่ยนประวัติจะแสดง “—” จนกว่าจะวิเคราะห์ใหม่
- ให้ AI เลือกและอธิบายจาก 5 สูตรอันดับแรก เมื่อเปิดสวิตช์และตั้งค่า Gemini แล้ว แสดง “เหตุผลจาก AI” ใต้ชุดเลขและชื่อสูตร
- คำนวณแผนภายในระบบ และแสดงบันทึกผลจริงใหม่เพื่อเทียบกับชุดเลขที่แสดงไว้ก่อนหน้า พร้อมดาวน์โหลดบันทึก CSV
- ส่วน `03 / PLAN & EVIDENCE` รวมแท็บแผน 20 งวด เปรียบเทียบทุกสูตร ผลทดสอบรายงวด และปุ่มส่งออกรายงานในส่วนนั้น ถูกนำออกจาก UI เหลือส่วนบันทึกตรวจผลใหม่หลังวิเคราะห์
- ฐานสูตรจัดการฝั่งเซิร์ฟเวอร์ หน้าผู้ใช้แสดงผลวิเคราะห์และรายงานโดยไม่ส่งออกตารางสูตรต้นฉบับ

## เข้าสู่ระบบและจัดการหลังบ้าน

ทุกคนต้องกรอก **รหัสผ่านอย่างเดียว** ก่อนเข้าใช้ ไม่ต้องมีชื่อผู้ใช้ ไม่มีรหัสเริ่มต้นที่ฝังในโค้ด และไม่เปิดหน้าใช้งานหากยังไม่ได้ตั้งค่าผู้ดูแล

- **รหัสสมาชิก:** เข้าหน้าวิเคราะห์ ไม่มีช่อง API key หรือชื่อโมเดล และไม่มีสิทธิ์เข้าหลังบ้าน
- **รหัสผู้ดูแล:** เข้าหน้าหลังบ้าน ตั้ง/เปลี่ยน Gemini API key, ชื่อโมเดล, รหัสสมาชิก และรหัสผู้ดูแล สลับไปหน้าใช้งานผ่านแถบด้านซ้ายได้
- รหัสสมาชิกเป็นรหัสร่วมกัน ต้องต่างจากรหัสผู้ดูแล ทั้งสองรหัสยาว 8–256 ตัวอักษร รหัสบันทึกเป็น PBKDF2-SHA256 พร้อม salt แยกแต่ละรหัส
- คีย์เดิมไม่ถูกเติมกลับลงช่องกรอก แม้ในหลังบ้าน เว้นช่องคีย์ใหม่ว่างไว้เพื่อคงคีย์เดิม หรือติ๊กเพื่อลบคีย์ การบันทึกคีย์ไม่ได้เรียก Gemini เพื่อตรวจโควตา
- เมื่อเปลี่ยนรหัส เซสชันของสิทธิ์นั้นต้องเข้าระบบใหม่ในการใช้งานครั้งถัดไป เซสชันหมดอายุภายใน 12 ชั่วโมงหรือเมื่อออกจากระบบ
- กรอกรหัสผิดรวม 10 ครั้งใน 5 นาที จะพักการเข้าสู่ระบบทั้งแอป 1 นาที ตัวนับเก็บฝั่งเซิร์ฟเวอร์ จึงไม่หายเมื่อรีเฟรชหน้า สมาชิกที่เข้าสู่ระบบแล้วใช้งานต่อได้

บนเซิร์ฟเวอร์ที่ไม่มีหน้าต่างคำสั่ง ให้ตั้งค่าเริ่มต้นใน Streamlit Secrets หรือคัดลอก `.streamlit/secrets.toml.example` เป็น `.streamlit/secrets.toml`:

```toml
ADMIN_PASSWORD = "your-distinct-admin-password"
APP_PASSWORD = "your-member-password"
GOOGLE_API_KEY = "your-key"
GEMINI_MODEL = "your-enabled-vision-model"
```

จำเป็นเฉพาะ `ADMIN_PASSWORD` สำหรับเริ่มต้น ส่วนสมาชิกและ AI ตั้งภายหลังในหลังบ้านได้ ค่า Secrets ใช้สร้างฐานข้อมูล **ครั้งแรกเท่านั้น** หลังจากนั้นใช้ค่าที่บันทึกในหลังบ้าน ไม่เขียนทับรหัสใหม่หรือกู้คีย์ที่ลบแล้วทุกครั้งที่รีเฟรช

ค่าบันทึกใน `.private/settings.db` บนเซิร์ฟเวอร์ ใช้ร่วมกันทุก session และคงอยู่เมื่อปิด/เปิดแอปบนเครื่องเดิม API key เป็นความลับที่แอปต้องอ่านได้ จัดเก็บในฐานข้อมูลฝั่งเซิร์ฟเวอร์ ไม่ได้แฮชแบบรหัสผ่าน ต้องจำกัดสิทธิ์อ่านไฟล์นี้และเก็บสำรองเป็นความลับ โฟลเดอร์ `.private/`, ฐานข้อมูล และ `.streamlit/secrets.toml` ถูกยกเว้นจาก Git ห้ามนำไปใส่ในโฟลเดอร์ static หรือแพ็กเป็น source แจกจ่าย

หากลืมรหัสผู้ดูแล ผู้ที่เข้าถึงเครื่องเซิร์ฟเวอร์สามารถตั้งใหม่ได้ด้วยคำสั่งต่อไปนี้ (ไม่ลบคีย์หรือรหัสสมาชิก):

```powershell
.\.venv\Scripts\python.exe setup_admin.py --reset
```

**การเก็บข้อมูลบน Streamlit Community Cloud:** [เอกสาร Streamlit](https://docs.streamlit.io/develop/concepts/connections/connecting-to-data) ไม่รับประกันความคงอยู่ของไฟล์ในเครื่อง หากฐานข้อมูลหาย แอปจะสร้างใหม่จาก Secrets และค่าที่เคยแก้ผ่านหลังบ้านจะหายด้วย เวอร์ชันนี้ใช้ SQLite ยังไม่มีตัวเชื่อมฐานข้อมูลภายนอก หากต้องการเก็บค่าหลังบ้านถาวร ให้รันบนเซิร์ฟเวอร์ที่มีดิสก์ถาวรและกำหนด `ZANI_SETTINGS_DB` ให้ชี้ไฟล์ในดิสก์นั้น หรือเพิ่มฐานข้อมูลภายนอกก่อนใช้งานจริงบน Community Cloud

กดอ่านภาพจะส่งภาพไป Gemini กดใช้ AI เลือกสูตรจะส่งประวัติและผลทดสอบที่เกี่ยวข้องไป Gemini ระบบไม่ได้ส่งภาพเมื่อเลือกกรอกเลขเอง

ทดสอบการเชื่อมต่อจริงกับโมเดล `gemini-3.5-flash-lite` ที่ตั้งค่าไว้เมื่อ 5 พฤศจิกายน 2026 แล้ว โดยอ่านภาพตัวเลขจำลองได้ `6 6 5 5` ถูกต้อง การทดสอบอัตโนมัติใช้ผลตอบกลับจำลองและตรวจโครงสร้างคำขอที่ SDK ส่งจริง ภาพของผู้ใช้ยังต้องตรวจเลขหลังอ่านทุกครั้ง และความพร้อมใช้งานขึ้นกับโควตาของบัญชีในขณะนั้น

หากอ่านภาพไม่สำเร็จ หน้าจอจะแจ้งหมวดปัญหา เช่น `AI-AUTH` (คีย์/สิทธิ์), `AI-MODEL-404` (โมเดล), `AI-QUOTA-429` (โควตา), `AI-CONNECTION` (เครือข่าย), `AI-TIMEOUT` (หมดเวลารอ) หรือ `AI-OUTPUT` (คำตอบผิดรูปแบบ) โดยไม่แสดงข้อความดิบจาก Google ที่อาจมีข้อมูลคำขอหรือคีย์

เมื่อ Google ตอบ 500/502/503/504 หรือเชื่อมต่อ/รอคำตอบไม่สำเร็จ แอปลองใหม่ด้วยโมเดลเดิมไม่เกิน 3 ครั้ง เว้นระยะประมาณ 2 และ 4 วินาที โดยกำหนดเวลารอต่อคำขอไม่เกิน 45 วินาทีและงบเวลารวม 90 วินาที ไม่ลองซ้ำอัตโนมัติสำหรับข้อผิดพลาดคีย์ สิทธิ์ โควตา หรือข้อมูลคำตอบไม่ถูกต้อง หากยังไม่สำเร็จ หน้าจอแสดงรหัสจริง เช่น `AI-SERVER-500` หรือ `AI-SERVER-503` เพื่อแยกปัญหาประมวลผลคำขอจากโมเดลไม่พร้อมให้บริการ บันทึกเซิร์ฟเวอร์เก็บเฉพาะประเภทงาน หมายเลขครั้ง HTTP status และชนิดข้อผิดพลาด ไม่บันทึกคีย์ ภาพ หรือข้อความคำขอ

ตรวจการลองใหม่กับ Gemini จริงแล้ว: ภาพตารางจำลอง 21 งวดได้รับ HTTP 503 ในคำขอแรก และอ่านเลขตรงกับข้อมูลต้นฉบับครบ 21 งวดในคำขอถัดไป การลองใหม่ไม่รับประกันว่าบริการภายนอกจะพร้อมเสมอ และยังต้องตรวจเลขจากภาพจริงก่อนยืนยัน

หลังพบ `gemini-3.5-flash-lite` ตอบ 503 ครบทั้ง 3 ครั้งในการใช้งานจริง ได้ทดสอบ `gemini-3.1-flash-lite` ด้วยคีย์เดิมและภาพจำลอง 21 งวด อ่านได้ตรงครบทั้งหมดโดยไม่มีคำเตือน จึงเปลี่ยนค่าบนเครื่องนี้เป็น `gemini-3.1-flash-lite` เมื่อ 5 พฤศจิกายน 2026 ผู้ดูแลยังเปลี่ยนโมเดลได้ในหลังบ้าน และไม่มีการสลับโมเดลอัตโนมัติ

คำขอใช้ schema แบบย่อที่ API รองรับ ส่วนขอบเขตเลข จำนวนช่อง และการปฏิเสธฟิลด์นอก schema ยังคงตรวจด้วย Pydantic ฝั่งแอป ไม่ส่ง `additionalProperties` และข้อกำหนดขนาดอาร์เรย์ขนาดใหญ่ผ่าน legacy `response_schema` เพราะคำขอเดิมถูก API ปฏิเสธด้วย HTTP 400

## ฐานสูตร Google Sheets

แหล่งข้อมูลที่ผู้ใช้ระบุ:
[ฐานข้อมูลสูตร / สูตร](https://docs.google.com/spreadsheets/d/1pV5479t6AY_-hIYYr5kUEjpUSGT0HDEFs-5Cbx03kiU/edit?gid=1717121509)

`data/formulas_snapshot.json` เป็นสำเนาที่อ่านผ่าน Google Drive connector เวลาใน `retrieved_at` เป็น UTC ไม่ใช่ข้อมูลสด แอปอ่านข้อมูลนี้ภายในระบบ ส่วนจัดการฐานสูตรถูกซ่อนจาก UI รวมทั้งลิงก์ชีต ตัวอัปโหลด CSV และปุ่มดาวน์โหลดสำเนาฐานสูตร

ชีตนี้ตอบ HTTP 401 เมื่ออ่านโดยไม่ยืนยันตัวตน จึงยังโหลดสดจากเว็บแอปแบบ anonymous ไม่ได้ สิทธิ์ Google Drive ใน Codex ไม่ได้ถูกส่งต่อให้ Streamlit อัตโนมัติ

การตั้งค่าสำหรับเชื่อมชีตส่วนตัวผ่านโมดูลฝั่งเซิร์ฟเวอร์ `sheets.py`:

1. เปิด Google Sheets API ใน Google Cloud project ของคุณ
2. สร้าง service account และ JSON key ในบัญชีของคุณ
3. แชร์ชีตที่ลิงก์ข้างต้นให้ `client_email` ของ service account เป็น **Viewer**
4. ใส่ข้อมูล JSON key เป็นตาราง `[gcp_service_account]` ใน Streamlit Secrets ตามไฟล์ตัวอย่าง ไม่วางคีย์ใน source
5. ผู้ดูแลเรียก `sheets.fetch_matrix` และตรวจด้วย `sheets.parse_matrix` ก่อนปรับปรุงสำเนาฝั่งเซิร์ฟเวอร์ แล้วเริ่ม session ใหม่เพื่อใช้ข้อมูลชุดใหม่

การนำเข้า CSV และโหลดชีตสดไม่มีปุ่มในหน้าผู้ใช้ การอัปเดตฐานข้อมูลทำฝั่งเซิร์ฟเวอร์

โครงสร้างข้อมูลต้องเป็น:

| เลขตั้งต้น | สูตร 1 | สูตร 2 | … |
|---|---|---|---|
| 0 | 456 | 146 | … |
| 1 | 567 | 257 | … |
| … | … | … | … |
| 9 | 345 | 035 | … |

ต้องมีเลขตั้งต้น 0–9 ครบ ไม่ซ้ำ แต่ละช่องมีเลขเว้น 3 ตัวไม่ซ้ำกัน อ่าน `058` ได้โดยรักษา 0 และรองรับช่องตัวเลข `58` เป็น `058` หากสูตรใดขาดหรือมีเลขซ้ำจะแจ้งคอลัมน์/เซลล์และไม่ใช้สูตรนั้น รองรับสูงสุด 200 สูตรในรูปแบบนี้ต่อชุด

## แผน 20 งวดหมายถึงอะไร

ผู้ใช้ยืนยันว่าต้องเปลี่ยนเลขตั้งต้นตามผลจริงทุกงวด จึงคำนวณงวดถัดไปจากประวัติจริงได้ทันที แต่งวดที่ 2–20 ยังไม่ทราบเลขตั้งต้นจริง:

- ค่าเริ่มต้นสมมติว่าผลล่าสุดออกซ้ำทุกงวด จึงอาจได้ชุดเลขเดิมทุกแถว
- หรือกรอกผลสมมติ 19 งวดเพื่อดูว่าชุดเลขจะเปลี่ยนอย่างไรตามสูตรเดิม
- ผลคำนวณภายในระบบแยกงวดที่ใช้ผลจริงกับผลสมมติ ตารางแผนและไฟล์ดาวน์โหลดแผนไม่ได้แสดงใน UI แล้ว
- เมื่อผลจริงออก กดเลข 1–9 หรือ 0 ในส่วน “เพิ่มผลจริงล่าสุด” ใต้ “เหตุผลจาก AI” ระบบตรวจชุดเลขงวดแรกที่เคยแสดง บันทึกเข้า/ไม่เข้า ล้างแผนเก่า แล้วให้กดวิเคราะห์ใหม่
- ภายในแผนสมมติใช้สูตรที่เลือกเดิมตลอด 20 งวด การเลือกสูตรใหม่ทำหลังมีผลจริงและกดวิเคราะห์ใหม่

การเลือก 7 จาก 10 มีฐาน 70% **เฉพาะเมื่อเลขทั้งหมดมีโอกาสเท่ากัน** อัตราย้อนหลังในแอปไม่ใช่ความมั่นใจงวดหน้า และไม่ใช่ผลกำไร การลองหลายสูตรบนประวัติชุดเดียวกันมีโอกาสเลือกสูตรที่บังเอิญเข้ากับอดีต จึงมีบันทึกผลใหม่หลังวิเคราะห์แยกไว้

## เครื่องคำนวณเงิน

เครื่องคำนวณเงินอยู่ในเมนู ☰ มุมขวาบนของหน้า ทั้งช่องตั้งค่าและผลคำนวณจะแสดงเมื่อเปิดเมนู ใช้เงินต่อเลขที่ผู้ใช้กรอกโดยตรงกับเลขที่เลือกทั้ง 7 ตัว อัตราจ่ายคงที่ **9.90 เท่ารวมทุน**: เลขละ 10 บาท × 7 เลข = ลงรวม 70 บาท ถ้าถูกหนึ่งเลขรับคืน 99 บาท กำไรสุทธิ 29 บาท ถ้าไม่ถูกขาดทุน 70 บาท

- กดเมนู ☰ มุมขวาบน กรอกทุนเริ่มต้นและเงินต่อเลข แล้วกด **บันทึก** ค่าจึงมีผล ตั้งค่าได้ตั้งแต่ก่อนวิเคราะห์ ค่าเริ่มต้นคือทุน 1,000 บาทและเงินต่อเลข 1 บาท ค่าที่บันทึกใช้ตลอด session นี้
- เครื่องคำนวณไม่ปรับจำนวนเงินตามสถิติหรือยอดจำลอง ไม่มีงบต่อรอบ จุดหยุด หรือคำแนะนำพักที่เปลี่ยนเงินเป็น 0 บาท
- เมื่อเพิ่มผลจริงหลังวิเคราะห์ บันทึกเงินต่อเลขและอัตราจ่ายที่แสดงไว้ก่อนงวดนั้น แล้วสะสมกำไร/ขาดทุนจากทุนเริ่มต้นที่บันทึก การเปลี่ยนเงินต่อเลขมีผลเฉพาะงวดถัดไป
- เมื่อเปลี่ยนทุนเริ่มต้น ยอดคงเหลือในแผง บันทึก และ CSV จะปรับตามทุนใหม่ โดยเก็บกำไร/ขาดทุนและเงินต่อเลขของแต่ละงวดไว้เดิม
- ย้อนกลับหนึ่งงวดจะคืนยอดของงวดนั้น การเปลี่ยนประวัติเริ่มยอดจำลองใหม่ตามทุนเริ่มต้นที่บันทึก
- ยอดทั้งหมดเป็นการคำนวณจำลองตามจำนวนเงินที่กรอก ไม่ใช่ยอดบัญชีเดิมพันจริง ยอดจำลองสามารถติดลบได้ เงินคืนปัดลงสองตำแหน่ง

## วิธีจัดอันดับ

ทุกสูตรใช้ช่วงทดสอบร่วมกัน ประเมินก่อนเปิดผลจริงของแต่ละงวด เรียงตามขอบล่าง Wilson 95% ของอัตราเข้า แล้วตามจำนวนพลาดต่อเนื่องน้อยที่สุด ใช้ id สูตรตัดสินเมื่อเท่ากัน ค่านี้เป็นเกณฑ์จัดอันดับย้อนหลัง ไม่มีการปรับ multiple comparisons และไม่ใช่หลักฐานความแม่นยำในอนาคต

AI เลือกได้เฉพาะสูตรใน shortlist ที่ทดสอบจริง Python เป็นผู้คำนวณชุดเลขทั้งหมด หาก AI เรียกไม่สำเร็จ จะแจ้งและใช้สูตรอันดับหนึ่งจากสถิติแทน โดยไม่แสดงว่าเป็นคำตอบจาก AI

ประวัติ แผน และฐานข้อมูลที่โหลดใหม่เก็บใน session ปัจจุบัน ปิด/รีเฟรชหรือรีสตาร์ตเซิร์ฟเวอร์อาจทำให้ข้อมูลหาย ดาวน์โหลดรายงานก่อนออกได้

## ทดสอบ

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

ตรวจหน้าเข้าสู่ระบบ สิทธิ์สมาชิก/ผู้ดูแล การบันทึกค่าข้ามเซสชัน การเปลี่ยนรหัสและเพิกถอนเซสชัน การจำกัดการลองรหัส การไม่แสดง API key เดิม รวมทั้งอ่านเลขซ้ำ/เลข 0, สูตรจริงครบ 108 × 10 เลขตั้งต้น, ไม่ใช้ผลอนาคตในการทดสอบย้อนหลัง, แผน 20 งวด, ภาพผิดรูปแบบ และ AI เลือกสูตรนอกฐาน ผ่าน unittest และ Streamlit AppTest โดยใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลจริง

ทดสอบเบราว์เซอร์เพิ่มเติมบนเครื่อง Windows ที่มี Edge เปิดเซิร์ฟเวอร์พอร์ต 8502 และตั้งรหัสสมาชิกแล้ว (สคริปต์จะถามรหัสสมาชิก และปิดสวิตช์ AI เพื่อไม่เรียก API):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tests\browser_smoke.py
```

ตรวจหน้าจอ desktop/mobile, เพิ่มผลจริง 0, เปลี่ยนผลสมมติ, ดาวน์โหลดบันทึกผลใหม่ CSV และยืนยันว่าส่วนแผนถูกนำออกจาก UI ภาพ QA บันทึกไว้ใน `dist/` ซึ่งไม่รวมใน source สำหรับ deploy
